# PC 게임 테스트 설계 — Section C · D

> 모바일 중심이던 검증 축을 넓히기 위해, 오래 플레이한 PC 게임 두 종을 대상으로 작성한 테스트 설계입니다.
> 총 **35건** (MMORPG 19건 · AOS 16건).

## 이 문서의 성격

**실제 플레이 경험을 바탕으로 구성한 가상 시나리오입니다.**
결과값(PASS / FAIL / BLOCK)은 검증 흐름을 보여주기 위한 설계상 가정이며, 실제 서비스에서 확인한 결함 보고가 아닙니다.

실행 기록과 실제 유저 제보는 Section A·B 및 버그 리포트를 참고해 주세요. 어느 쪽이 무엇인지 구분해두는 것이 문서 전체의 신뢰를 지키는 방법이라고 생각했습니다.

## 두 시트를 나눈 이유

장르가 달라지면 봐야 할 곳도 달라집니다. 같은 축을 반복하지 않고 차이가 드러나도록 구성했습니다.

| | Section C (MMORPG) | Section D (AOS) |
|:--|:--|:--|
| 성격 | 영속 데이터 | 1회성 매치 |
| 핵심 질문 | 데이터가 제대로 남는가 | 실시간으로 제대로 도는가 |
| 고유 축 | 재화 정합성, 강화 수치 상한, 인벤토리 한계 | 전투 중·이동 중·사망 상태의 기능 제약 |

양쪽 모두 **해상도 변경 · 창모드 전환 · Alt+Tab · 키 바인딩** 등 모바일에는 없는 PC 고유 검증 축을 포함했습니다.

## 결과 표기

| 값 | 의미 |
|:--|:--|
| PASS | 예상 결과와 일치 |
| FAIL | 예상 결과와 불일치 |
| BLOCK | 선행 TC 실패로 실행 불가 |
| N/A | 해당 없음 |
| N/T | 미실행 |

아래 표는 목록 요약입니다. **사전 조건 · 절차 · 예상 결과 · 실제 결과**를 포함한 전체 항목은 원본 엑셀(`이영준_QA포트폴리오_PC_TC.xlsx`)에 있으며, FAIL·BLOCK 항목은 이 문서 하단에 상세를 실었습니다.

## FAIL · BLOCK 상세

결함으로 판정했거나 선행 실패로 막힌 항목입니다. 나머지 PASS 항목의 절차와 예상 결과는 원본 엑셀을 참고해 주세요.

### Section C

#### DF-007 · 강화 실행 — 실패 — FAIL / Minor / 재현율 2/5(40%)

- **사전 조건** — DF-006 통과, 골드 충분
- **절차** — 1. 강화 실행 2. 실패 결과 확인 3. 장비 상태·재화 확인
- **예상 결과** — 실패 안내 출력, 재료·골드는 차감, 장비는 규칙에 따른 상태로 처리
- **실제 결과** — 강화 실패 시 결과창은 실패로 표기되나, 인벤토리의 장비 상태 갱신이 즉시 반영되지 않고 창을 다시 열어야 반영됨
- **설계 근거** — 실패 경로. 재화는 차감되나 결과물이 없어 분쟁이 잦은 구간

#### DF-008 · 강화 결과 연출 — BLOCK

- **사전 조건** — DF-006 또는 DF-007 수행
- **절차** — 1. 강화 실행 2. 연출 확인 3. 실제 결과와 대조
- **예상 결과** — 연출 결과와 실제 적용 결과가 일치
- **실제 결과** — DF-007 실패 결과 반영 지연으로 연출과 실제 결과 대조 불가
- **설계 근거** — 연출과 실제 결과 불일치는 유저 신뢰에 직접 영향 / 선행 DF-006·DF-007

#### DF-012 · 해상도 변경 시 UI — FAIL / Minor / 재현율 3/3(100%)

- **사전 조건** — 강화 창 진입 상태
- **절차** — 1. 강화 창 진입 2. 옵션에서 해상도 변경 3. 강화 창 UI 확인
- **예상 결과** — UI 요소 잘림·겹침 없이 해상도에 맞게 재배치
- **실제 결과** — 해상도 1920x1080 → 1280x720 변경 시 강화 창 우측 UI 일부가 화면 밖으로 잘림
- **설계 근거** — PC 고유. 해상도별 UI 레이아웃은 모바일에 없는 검증 축 / PC 환경

#### DF-017 · 강화 버튼 연속 입력 — FAIL / Major / 재현율 4/5(80%)

- **사전 조건** — 장비·재료 등록 완료 상태
- **절차** — 1. 강화 버튼을 빠르게 5회 연속 클릭 2. 결과·재화 확인
- **예상 결과** — 1회만 실행, 재화 1회분만 차감
- **실제 결과** — 5회 연속 클릭 시 강화 2회 실행, 재료·골드 2회분 차감
- **설계 근거** — 연속 입력 방지 미구현 시 재화 다중 차감 발생 / 예외 입력

### Section D

#### ER-011 · 이동 중 제작 — FAIL / Minor / 재현율 3/5(60%)

- **사전 조건** — 캐릭터 이동 중
- **절차** — 1. 이동 명령 입력 2. 이동 중 제작 실행
- **예상 결과** — 규칙에 따라 정지 후 제작
- **실제 결과** — 이동 중 제작 실행 시 캐릭터가 정지하지 않고 제작도 실행되지 않음
- **설계 근거** — AOS 고유. 이동 명령과 제작 명령의 우선순위 확인 / 매치 제약

## FAIL 배치 근거

| TC | 내용 | 근거 |
|:--|:--|:--|
| DF-007 | 강화 실패 결과의 인벤토리 반영 지연 | 상태 갱신 누락은 실제로 자주 보고되는 유형 |
| DF-012 | 해상도 변경 시 UI 잘림 | PC 게임에서 흔한 레이아웃 결함 |
| DF-017 | 연속 입력 시 재화 다중 차감 | 입력 방지 미구현 시 발생 |
| ER-011 | 이동 중 제작 명령 충돌 | AOS에서 명령 우선순위 이슈로 발생 |

**Critical은 두지 않았습니다.** 라이브 서비스 중인 타이틀에 치명 결함을 가정하는 것은 시나리오로서 부자연스럽다고 판단했습니다.

## BLOCK 처리 원칙

선행 TC가 막히면 후속 TC를 BLOCK으로 처리하되, **실행 순서상 앞선 TC만 후속 TC의 BLOCK 원인이 될 수 있도록** 배치했습니다. 뒤에 실행할 TC 때문에 앞 TC가 막히는 구조는 성립하지 않기 때문입니다.

Section D에는 BLOCK을 두지 않았습니다. 이동 상태와 사망 상태는 서로 독립이라 선행 의존 관계가 성립하지 않아, 억지로 연결하는 대신 각각 독립 TC로 두었습니다.
